# Phase 2: Chain-of-Thought SQL Planning

You are analyzing a natural language question about Gulf Coast bird colony data to plan a SQL query.

## Your Task

**DO NOT write SQL yet.** Think step-by-step and explain your reasoning.

## Analysis Framework

### 1. Question Understanding
- What is the user asking for?
- What type of answer do they expect? (count, list, comparison, trend, location)
- Are there implicit requirements? (e.g., "where" questions need coordinates)

### 2. Table Selection
- **Primary data**: Use `tblColonyTotals2010-2021_MayJuneCombined` for bird/nest counts
- **Reference data**: Use `tblSpeciesCodes` for species names
- **Metadata**: Use `tblRWCWB_ColonyInventory_10Nov22` for colony details
- **DO NOT use**: `tblSpeciesData*` tables (photo records, not bird counts)

### 3. Column Requirements
- What columns does the question mention? (Year, ColonyName, State, etc.)
- Does it need counts? (`SUM(COALESCE(CAST("Birds" AS REAL), 0))`)
- Does it need geography? **ALWAYS include Latitude, Longitude for location questions**
- Does it need species names? (Join to tblSpeciesCodes)

### 4. Query Structure
- **Simple SELECT**: Single table, straightforward columns
- **Aggregation**: GROUP BY needed? Which columns?
- **JOIN**: Multiple tables? Which join keys?
- **CTE (WITH)**: Complex logic that needs breaking down?
- **Window functions**: Rankings, running totals?

### 5. Filters & Conditions
- Year filter? (`WHERE "Year" = 'YYYY'`)
- State/region filter? (`WHERE "State" = 'XX'`)
- Species filter? (`WHERE "SpeciesCode" = 'XXXX'`)
- **Geographic filter**: `WHERE "Latitude" IS NOT NULL AND "Longitude" IS NOT NULL`

### 6. Ordering & Limits
- How should results be sorted? (BY count DESC, by Year ASC)
- Should we limit results? (TOP 10, TOP 20)
