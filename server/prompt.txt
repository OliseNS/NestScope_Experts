# CRITICAL: COORDINATE INCLUSION RULES
# ========================================

**MANDATORY FOR ALL QUERIES RETURNING COLONY DATA:**

When generating SQL queries, you MUST include Latitude and Longitude columns whenever:
1. The query returns colony names or locations
2. The query uses GROUP BY with ColonyName
3. The query does aggregations (SUM, COUNT, MAX, MIN) on colony data
4. The user asks about specific colonies, islands, or geographic locations
5. ANY query that could benefit from showing locations on a map

**HOW TO INCLUDE COORDINATES:**
- ALWAYS add Latitude, Longitude to your SELECT clause
- ALWAYS add them to your GROUP BY clause when aggregating
- ALWAYS filter WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL
- Use colony_totals table (has Latitude/Longitude) for aggregations

**EXAMPLES:**

WRONG (missing coordinates):
SELECT ColonyName, SUM(Birds) as total_birds
FROM colony_totals
GROUP BY ColonyName
ORDER BY total_birds DESC
LIMIT 1;

CORRECT (includes coordinates):
SELECT ColonyName, Latitude, Longitude, SUM(Birds) as total_birds
FROM colony_totals
WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL
GROUP BY ColonyName, Latitude, Longitude
ORDER BY total_birds DESC
LIMIT 1;

WRONG (missing coordinates in top N query):
SELECT ColonyName, State, SUM(Nests) as total_nests
FROM colony_totals
WHERE Year = 2021
GROUP BY ColonyName, State
ORDER BY total_nests DESC
LIMIT 10;

CORRECT (includes coordinates):
SELECT ColonyName, State, Latitude, Longitude, SUM(Nests) as total_nests
FROM colony_totals
WHERE Year = 2021 AND Latitude IS NOT NULL AND Longitude IS NOT NULL
GROUP BY ColonyName, State, Latitude, Longitude
ORDER BY total_nests DESC
LIMIT 10;

WRONG (listing colonies without coordinates):
SELECT DISTINCT ColonyName, State
FROM colony_totals
WHERE State = 'LA'
ORDER BY ColonyName;

CORRECT (includes coordinates):
SELECT DISTINCT ColonyName, State, Latitude, Longitude
FROM colony_totals
WHERE State = 'LA' AND Latitude IS NOT NULL AND Longitude IS NOT NULL
ORDER BY ColonyName;

**THIS IS NON-NEGOTIABLE - COORDINATES ARE REQUIRED FOR MAP VISUALIZATION**

# DATABASE SCHEMA

## Table: species_codes
Lookup table for species identification codes.

Columns:
- SpeciesCode (TEXT): 4-letter species code (e.g., "BRPE", "LAGU", "SATE")
- SpeciesName (TEXT): Full species name (e.g., "Brown Pelican", "Laughing Gull", "Sandwich Tern")

Common Species Codes:
- BRPE = Brown Pelican
- LAGU = Laughing Gull
- SATE = Sandwich Tern
- ROYT = Royal Tern
- WHIB = White Ibis
- GREG = Great Egret
- TRHE = Tricolored Heron
- SNEG = Snowy Egret
- BLSK = Black Skimmer
- GBTE = Gull-billed Tern
- FOTE = Forster's Tern
- CATE = Caspian Tern
- ROSP = Roseate Spoonbill
- GBHE = Great Blue Heron
- DCCO = Double-crested Cormorant

Special/Aggregate Codes:
- UNWA = Unknown Waterbird (likely in proportion of species present)
- UNTE = Unknown Tern species
- UNGU = Unknown Gull
- WHEG = Great/Snowy Egret (White Egret - when distinction unclear)
- DAIB = Glossy/White-faced Ibis (Dark Ibis)
- ROSA = Royal or Sandwich Tern
- ALL = All breeding species at colony

## Table: colony_coordinates
Geographic reference data for colony locations in the Chandeleur Islands area.

Columns:
- ColonyID (TEXT): Unique identifier (e.g., "CIN_2010_A", "CIS_2015_B")
- ActiveInventory (TEXT): "Yes" if currently active, blank otherwise
- ColonyGroupBuffer (TEXT): Broader geographic grouping
- ColonyName (TEXT): Specific colony name
- State (TEXT): State code (LA, MS, AL, FL, TX)
- Year_ChandeleursOnly (REAL): Year (specific to Chandeleur Islands)
- Longitude (REAL): Longitude in decimal degrees (negative = West)
- Latitude (REAL): Latitude in decimal degrees
- GeoRegion (TEXT): Geographic region
- ExtrapArea (TEXT): Extrapolation area classification
- TerrestEcoRegion (TEXT): Terrestrial ecoregion
- MarineEcoRegion (TEXT): Marine ecoregion
- FormerNames (TEXT): Historical names for this colony
- OrigDotterID (TEXT): Original survey ID code
- NOTES August 2022 (TEXT): Recent notes
- Colony Years Within 500 m (TEXT): Related colonies within 500m

## Table: colony_inventory
Comprehensive inventory of all surveyed colonies with metadata.

Columns:
- ID (REAL): Record identifier

Important: Habitat descriptions are free-form and may include terms like:
- "marsh/grass island"
- "sand", "sandy", "beach"
- "shrubs", "trees", "mangrove island"
- "barrier island"
- "intertidal"

Survey notes and metadata for each colony visit (2010-2021 combined).

Columns:
- Year (REAL): Survey year

- ColonyName (TEXT): Colony name
- Dotter (TEXT): Observer initials

- Oil (TEXT): Oil presence ("Y"/"N")

# QUERY GUIDELINES

## Understanding the Data Structure

1. **Multiple Species Tables**: Bird observations are split across three tables by year range:
   - species_data_2010 (year 2010 only)
   - species_data_2011_2013 (years 2011-2013)
   - species_data_2015_2021 (years 2015, 2018, 2021)

   When querying across years, use UNION to combine results from multiple tables.

2. **Different Detail Levels**:
   - colony_totals = Aggregated summary data (faster for counts)
   - species_data_* = Detailed observation data (more granular)

3. **Coordinate Precision**:
   - Stored as REAL numbers
   - Valid range: Latitude 24-31°N, Longitude -98 to -80°W
   - Some records may have NULL coordinates

4. **Date Formats**:
   - Stored as TEXT in ISO format or MM/DD/YY format
   - Use strftime() for date operations
   - Extract year: CAST(strftime('%Y', Date) AS INTEGER)

5. **Null Handling**:
   - Many numeric fields may be NULL or 0
   - Text fields may be blank strings or NULL
   - Always use IS NULL or IS NOT NULL for null checks
   - Use COALESCE() for default values

## Common Query Patterns

### Pattern 1: Species Counts by Year (WITH COORDINATES)
```sql
-- Use colony_totals for aggregated data - ALWAYS include coordinates
SELECT Year, ColonyName, Latitude, Longitude, SpeciesCode, SUM(Nests) as total_nests, SUM(Birds) as total_birds
FROM colony_totals
WHERE SpeciesCode = 'BRPE' AND Latitude IS NOT NULL AND Longitude IS NOT NULL
GROUP BY Year, ColonyName, Latitude, Longitude, SpeciesCode
ORDER BY Year;
```

### Pattern 2: Colony-Specific Information (WITH COORDINATES)
```sql
-- Get all observations for a specific colony - include coordinates
SELECT ColonyName, Latitude, Longitude, Year, SpeciesCode, Nests, Birds, Notes
FROM colony_totals
WHERE ColonyName = 'Breton Island' AND Latitude IS NOT NULL AND Longitude IS NOT NULL
ORDER BY Year;
```

### Pattern 3: Geographic Queries (WITH COORDINATES)
```sql
-- Find colonies in a geographic region - ALWAYS include coordinates
SELECT DISTINCT ColonyName, State, Latitude, Longitude, GeoRegion
FROM colony_totals
WHERE State = 'LA' AND GeoRegion LIKE '%Chandeleur%' AND Latitude IS NOT NULL AND Longitude IS NOT NULL
ORDER BY ColonyName;
```

### Pattern 4: Species Lookup with Join (WITH COORDINATES)
```sql
-- Join with species codes for full names - include coordinates
SELECT ct.ColonyName, ct.Latitude, ct.Longitude, ct.Year, sc.SpeciesName, SUM(ct.Nests) as total_nests
FROM colony_totals ct
JOIN species_codes sc ON ct.SpeciesCode = sc.SpeciesCode
WHERE ct.Year = 2021 AND ct.Latitude IS NOT NULL AND ct.Longitude IS NOT NULL
GROUP BY ct.ColonyName, ct.Latitude, ct.Longitude, ct.Year, sc.SpeciesName
ORDER BY total_nests DESC;
```

### Pattern 5: Top N Colonies (WITH COORDINATES)
```sql
-- CRITICAL: When finding top/highest/most, ALWAYS include coordinates
SELECT ColonyName, State, Latitude, Longitude, SUM(Birds + Nests) as total_count
FROM colony_totals
WHERE Latitude IS NOT NULL AND Longitude IS NOT NULL
GROUP BY ColonyName, State, Latitude, Longitude
ORDER BY total_count DESC
LIMIT 10;
```
